# Image Versioning Report

## 1. Immutable Semantic Versioning
The deployment architecture has been completely decoupled from the unstable `latest` tag pattern. We are strictly enforcing Immutable Semantic Versioning (SemVer) for all production rollouts.

### Format
All deployments will reference an exact version string in the `docker-compose.client.yml` file, injected via the `.env.client` configuration.
- **Example Tags**: `v1.0.0`, `v1.0.1`, `v1.1.0`, `v2.0.0`

### Implementation
- The client `docker-compose.client.yml` now utilizes the variable `${APP_VERSION:-v1.0.0}` to strictly bind the deployment to a known, verified state.
- While a `latest` tag may still be generated by the CI pipeline for internal testing or generic pulls, **production servers will never deploy unpinned latest tags**.

## 2. Benefits
This strategy allows for:
- **Absolute Traceability**: We know exactly which codebase is running on the client server.
- **Reliable Rollbacks**: If `v1.1.0` fails post-deployment verification, the deployment script can safely revert the environment variable to `v1.0.0` and bring the system back to the exact previous stable state.
